模块按 `core`/`impl`/`annotation`/`config`/`sync` 分层组织：
- `core` 定义核心契约：`Cache<T>`（单级）、`MultiCache<T>`（继承 Cache 并扩展 nextLevelCache 链式加载）、`CacheManager`（按 category 创建/获取 Cache）、`CacheTemplate`（对外模板）、`CacheWrapper`（值+过期时间包装）；击穿防护通过依赖 `common-lock` 的 `LockSupport.lockAndExecuteOnce` / `lockAndExecuteQueued` 在接口默认方法中统一实现。
- `impl` 提供具体存储：`HashMapCache`/`CaffeineCache`（本地）、`RemoteRedisCache`/`MultiRemoteRedisCache`（远程 Redis），以及组合型 `DistributeCache`（装饰器，写操作后发布 `CacheSyncMessageImpl`）、`MultiHashMapCache`（L1=本地 + L2=MultiCache）。
- `annotation` 暴露 `@MethodCache` + `@EnableCache`，由 `MethodCacheAspect` 基于 AOP 拦截方法调用，委托 `CacheManager` 完成存取。
- `config.CacheAutoConfiguration` 作为 Spring Boot 自动装配入口，注册全局 `globalCache`、`cacheManager`、`cacheRedisTemplate`（Jackson2Json 序列化）、`l1Cache`（MultiHashMapCache）与 `l2Cache`（MultiRemoteRedisCache，@Primary），并启用 `@EnableLock`。
- `sync` 子包封装基于 Redis Pub/Sub 的节点间缓存同步：`CacheMessagePubSub` 单例、`CacheNodeRegisterInfo` 节点注册信息、`RedisCacheMessagePub`/`RedisCacheMessageSub` 具体实现，配合 `CacheSyncMessage` 系列对象传递 category/key/ttl 变更事件。
依赖方向：`impl` → `core` → `sync`；`config` 装配所有层；`annotation` 仅依赖 `core` 并通过 AspectJ 切入业务方法。
