## 关键约束与风险

| 约束 | 说明 |
|------|------|
| **T-15 依赖 T-09** | `ConfigAdminService` 事务保护先做，否则 `deleteConfigs` 加 `triggerListeners` 后回滚行为不确定 |
| **T-14 需联合发版** | `pull` 路径改动需 admin-server 和 client-sdk 同步发版，否则客户端拉取配置失败 |
| **T-05 可独立验证** | `StatsAlertService` 纯后端计算，先写单元测试覆盖，前端 T-12 只做展示 |
| **T-11 分布式锁** | `@Scheduled` 定时任务使用 `RedissonSyncLock.tryLock` 防多节点并发，未获取锁则跳过执行。需添加 `@EnableScheduling` 注解（当前未开启） |
| **T-11 表结构变更** | `thread_pool_stats_daily` 表需要 DBA 评审，确认索引和分区策略 |
| **T-09 跨 Storage 事务** | `createApp` 涉及 `ApiKeyStorage` 和 `ConfigStorage` 两个独立 Bean，需使用 `TransactionTemplate` 编程式事务 |
| **T-13a/T-13b 契约先行** | 先固定 health 三态响应和 HTTP 状态码语义，再实现 SDK Router；避免客户端把 `DEGRADED` 误判为不可用节点 |
| **T-13b 不引入 SPI/服务发现** | 路由算法通过配置文件 + Spring Boot 属性优先级选择；不引入 SPI，不引入 Nacos/Consul 等服务发现依赖 |
| **T-13b 熔断与健康检查独立** | 健康刷新负责主动摘除/恢复节点；节点级熔断负责请求过程中连续失败，二者状态独立但共同影响候选池 |
