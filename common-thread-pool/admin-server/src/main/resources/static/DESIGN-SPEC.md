# ThreadPool Admin UI Design Spec

> **版本**: v1.0  
> **模块**: `common-thread-pool/admin-server/src/main/resources/static/`  
> **风格**: 现代极简 · 强联动 · 纯 CSS 自研  
> **日期**: 2026-07-12

---

## 1. 设计原则

| 原则 | 体现 |
|------|------|
| **信息密度平衡** | 仪表盘一屏看全局（4 卡 + 主表 + 告警 + 活动），详情页深而精 |
| **零页面跳转** | 列表 → 编辑器 → 差异预览 → 保存反馈 全部在同一页内完成 |
| **乐观更新** | 操作后立即视觉反馈，失败回滚+红框提示 |
| **空状态友好** | 每个列表都有 Empty state 引导（创建按钮 + 简短说明） |
| **键盘友好** | `⌘K` 全局搜索、`/` 聚焦搜索框、`Esc` 关闭抽屉 |
| **暗色模式预留** | CSS 变量驱动，`@media (prefers-color-scheme: dark)` 一键切换 |

## 3. 核心组件

### 3.1 顶栏（Topbar）

```
[Logo T]  [仪表盘] [线程池] [API Keys] [监控] [审计]    [● 实时同步] [WL Wang Lei]
```

- 高 52px，白底，下边框 1px
- 激活项：`bg: accent-soft, color: accent, weight: 500`
- 实时同步指示器：脉冲点 + 文字
- 用户区：渐变头像 + 昵称

### 3.2 应用选择器（App Switcher）

跨页面的"全局上下文"，是联动的核心：

```
[O] order-service  [v42]  ▾
```

- 点击展开下拉，列出所有应用 + 在线状态
- 选择后整个页面（仪表盘、池列表、监控）联动刷新
- 状态记忆到 `localStorage` + URL 参数（`?app=order-service`）

### 3.3 指标卡（Stat Card）

```
┌──────────────┐
│ 应用数        │  ← 11px 灰
│      8        │  ← 26px 黑 (letter-spacing: -0.02em)
│ ↑ 1 本周     │  ← 11px (绿/红/灰)
└──────────────┘
```

变体：
- **普通**：白底 + 边框
- **告警**（异常线程池数）：红色边框 + 顶部红色脉冲点 + 淡红渐变背景

### 3.4 池列表（带联动）

```
┌──────────────┬────────┬──────────┬────────┬────────┐
│ 池名          │ 核心/最大│ 队列使用  │ 拒绝率  │ 状态   │
├──────────────┼────────┼──────────┼────────┼────────┤

- 队列使用列：7 段 sparkline（CSS bar），按 0-50% 蓝 / 50-80% 黄 / 80%+ 红

- 状态栏：4 种 badge —— 健康/关注/告警/空闲

- 32px 圆角图标方块（淡红背景 + 红色字符）
- 标题：池名 + 异常指标徽章

### 3.8 Sparkline（内联迷你图）

纯 CSS 实现，7 段柱状，高度 30px：
- 默认：`bg: accent-soft`
- 警告段（> 50%）：`bg: warn-soft`
- 危险段（> 80%）：`bg: danger-soft`

### 3.9 Toast（成功提示）

```
┌─────────────────────────────────┐
│ ● 已保存为 v42 · 3 客户端已通知 │

```

```

紧凑列表，徽章区分操作类型，单行高度 28px。

## 4. 联动机制

### 4.1 全局应用切换联动

| 触发 | 响应 |
|------|------|
| 切换 App Switcher | 仪表盘 4 卡 + 主表 + 告警 + 活动 全部无刷新重渲染（Fetch + DOM patch） |
| URL 携带 `?app=` 参数 | 直接定位到指定应用 |
| 选择后 `localStorage.setItem('currentApp', appId)` | 下次访问默认进入 |

### 4.2 列表→编辑器联动

```
点击池行
  ↓
该行高亮（左侧 3px accent border + 浅蓝背景）
  ↓
右侧抽屉从 translateX(100%) 滑入（200ms ease-out）
  ↓
抽屉内：模板回填 + 表单可编辑 + 变更字段高亮
  ↓
点"查看差异" → 抽屉内嵌 diff 面板（不打开新模态）
```

**实现要点**：
- 抽屉用 CSS `transform: translateX()` 而非 `position` 变化 → 触发 GPU 加速，丝滑
- 表单变化用 `dirtyFields` Set 追踪 → 只高亮真正修改的字段
- 抽屉打开时主内容区加 `padding-right: 480px` 避免布局跳动

### 4.3 乐观更新（Optimistic Update）

```
点"保存"
  ↓ (立即)
抽屉关闭 + 列表对应行加绿色高亮渐变（3s 渐隐）
  ↓
更新本地缓存（v41 → v42）
  ↓ (异步)
POST /api/.../save
  ↓
成功 → Toast 绿色提示"已保存为 v42 · N 客户端已通知"
失败 → 回滚本地状态 + 行红框闪烁 + Toast 红色提示
```

### 4.4 实时告警（可选，需 SSE/WebSocket）

- 仪表盘告警卡片数字脉冲更新
- 列表对应行即时变红 + 添加"告警"徽章
- 全局告警数 +1，导航栏可加红色角标

### 4.5 键盘快捷键

| 键 | 行为 |
|----|------|
| `⌘K` / `Ctrl+K` | 打开全局搜索（应用、池、Key） |
| `/` | 聚焦当前页搜索框 |
| `Esc` | 关闭抽屉/模态 |
| `n` | 新建（当前上下文） |
| `e` | 编辑当前选中项 |
| `?` | 显示快捷键帮助 |

## 7. 可访问性

- 所有交互元素键盘可达（Tab 顺序合理）
- 焦点环明显：`outline: 2px solid var(--color-accent); outline-offset: 2px`
- 颜色对比度 WCAG AA（正文 ≥ 4.5:1）
- 图标按钮带 `aria-label`
- 抽屉打开时焦点 trap，关闭时焦点回到触发元素
- `prefers-reduced-motion: reduce` 时关闭过渡动画

---

## 8. 性能预算

- 首屏 LCP < 1.5s（HTML + CSS 内联，JS 异步）
- 抽屉滑入 60fps（仅 transform，不触发布局）
- 列表渲染 < 100ms（100 行）
- Toast/Sparkline 纯 CSS，无 JS 动画开销
