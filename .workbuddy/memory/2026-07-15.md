## PRD v3.0 → v3.1 + 任务拆分修正（T-03/T-11/T-13）

### 用户指出的三个问题
1. **T-03 不对**：`AdminAuthService` 在 `AdminServerAutoConfiguration` 第 131 行通过 `@Bean` 注册，Spring 对 `@Bean` 方法返回对象同样支持 AOP 代理，与 `@Service` 扫描等效。ARCH-05 是误判。
2. **T-11 分布式场景风险**：`@Scheduled(cron = "0 0 2 * * ?")` 多实例同时触发会重算。项目已有 `RedissonSyncLock`，直接用 `redissonClient.getLock("stats:aggregation").tryLock(0, 120, s)` 加固。
3. **T-13 目标缺失**：健康检查不是只返回 UP，需要形成「健康检查 → 监控采集 → 告警通知 → 运维响应」完整链路。补充了 SDK 退避机制、K8s liveness probe、Prometheus blackbox_exporter 集成。

- **PRD v3.1**：ARCH-05 标记为非问题，F2-U-01 删除，F2-T-04/05 增加分布式锁，F2-O-01 扩展为完整监控链路，工期从 11d 降至 10.5d

## T-11 / T-13 第二轮修正（用户反馈）

### T-11 分布式锁实现方式
不再直接操作 `redissonClient.getLock().tryLock()`，改为在 `RedissonSyncLock` 中新增 `tryLock(String lockName, String key, long waitTime, long leaseTime, TimeUnit): boolean` 方法，遵循项目已有的锁抽象层。`StatsAggregationService` 注入 `SyncLock` 调用。

### T-13 重写为 admin-server 高可用
用户澄清意图：不是做 poll/pull 前的健康检查，也不是做运维监控集成——目标是 **admin-server 高可用**：客户端 SDK 配置多个 admin-server 地址，当前节点故障时自动切换到健康节点。关键设计：
- 🅰 Server：`GET /open/api/thread-pool/health` 返回 DB + Redis 连接状态
- 🅲 SDK：`ConfigServerClient` 支持多地址 + unhealthy/healthy 标记 + 自动故障切换 + 后台定期探测恢复
- 运维集成（K8s probe/Prometheus）留待 v3.1
